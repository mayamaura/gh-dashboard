# GitHub Copilot 稼働ダッシュボード / プロジェクトダッシュボード 要求仕様書

- **版**: 1.0 / 2026-09-03

GitHub Copilot (Copilot CLI / VS Code の Copilot Chat・エージェントモード) の稼働状況と利用枠の消費を可視化し、あわせてローカルの開発プロジェクトを一覧・起動できる、**Windows 常駐型のデスクトップアプリ**に対する要求をまとめる。2 つのタブ (Copilot / プロジェクト) からなる 1 アプリを想定する。

---

## 0. この文書の読み方

### 0.1 要求 ID

| プレフィクス | 領域 |
|---|---|
| `FR-P-nn` | 機能要求: プロジェクト機能 |
| `FR-C-nn` | 機能要求: Copilot 稼働ダッシュボード |
| `DR-nn` | データ要求 (永続化) |
| `IR-nn` | 外部インタフェース要求 (コマンド / イベント) |
| `NFR-nn` | 非機能要求 |
| `OQ-nn` | 未決事項 (着手前に実測で確定させる項目) |

要求 ID は欠番が出ても詰めず、削除した ID は再利用しない。

### 0.2 優先度

| 記号 | 意味 |
|---|---|
| **必須** | これが無ければ機能として成立しない (MUST) |
| **推奨** | 無くても動くが、実運用で必ず問題になる (SHOULD) |
| **任意** | あると良い (MAY)。v1 で落としてよい |

### 0.3 確度の表記

本書は GitHub Copilot がローカルに残すデータと公開 API に依存する。**公式ドキュメントで確認できた事実**と、**実測で確定させる必要がある事項**を区別して書く。後者は付録 B に `OQ-nn` として集約し、本文からは ID で参照する。

**Copilot のセッションログは内部形式であり、バージョンアップで予告なく変わりうる。** 本書の要求はその前提に立って書かれている (FR-C-13、NFR-23)。

## 1. 目的

### 1.1 解決する課題

**A. コーディングエージェントの稼働が見えない**

複数の VS Code ウィンドウとターミナルで Copilot を並行運用すると、次が把握できなくなる。

1. 利用枠 (AI Credits / クォータ) の消費状況がすぐに見えない
2. どのセッションが今動いていて、どれが止まっているか分からない
3. どのエージェントがどのサブエージェント・委任タスクに指示を出しているかが見えない
4. 「どうエージェントが動いたか」を後から振り返る手段がない

**B. 開発中プロジェクトの所在と状態が見えない**

5. 動かすたびに「フォルダを思い出す → エクスプローラーを開く → ターミナルを開く → `npm run dev` → 採番されたポートを確認」を繰り返している
6. どれを最後にいつ触ったか、どれが放置されているかを一覧で把握できていない

### 1.2 想定利用者

開発者本人 1 名 (個人利用)。配布・マルチユーザー対応・組織展開は目的としない。

## 2. スコープ

### 2.1 対象範囲

| # | 範囲 |
|---|---|
| S-1 | Copilot セッションのログの**差分インデックス**と、それを元にしたセッション一覧・系統図・ガント・本文ビューア |
| S-2 | 稼働中セッションの**ライブ監視** (どれが動いていて、何をしているか) |
| S-3 | **利用枠に対する消費率**の可視化 (AI Credits / クォータ / コンテキストウィンドウ) |
| S-4 | **本日の使用状況**ダイジェスト (トークン、ターン数、クレジット、時間帯別推移、フォルダ別内訳) |
| S-5 | ローカル開発プロジェクトの**自動スキャン・一覧・詳細**、git 状態、Copilot 利用状況の紐付け |
| S-6 | dev サーバーの**起動 / 停止 / ログ / URL 検出** |
| S-7 | 外部ツール連携 (VS Code / エクスプローラー / ターミナル / Copilot CLI / ブラウザで開く) |

### 2.2 非対象

| # | やらないこと | 理由 |
|---|---|---|
| N-1 | Copilot セッションの再開・強制終了・エージェントへの介入 | 「見る・振り返る」に集中する。誤操作の代償が読み取り専用機能とは桁違い |
| N-2 | プロジェクトの作成・削除・移動 | 同上 |
| N-3 | ビルド / テスト / デプロイの実行 | dev サーバー起動以外のプロセス管理を持ち込まない |
| N-4 | git 操作 (commit / push / pull / branch) | VS Code / ターミナルと責務が重複する。**表示のみ** |
| N-5 | Copilot の既存設定ファイル (`settings.json` / `config.json`) の書き換え | **一切行わない。Copilot 側のデータはすべて読み取り専用**。ファイルを置く必要が生じても、既存ファイルの編集ではなく新規ファイルの追加に限る |
| N-6 | 認証情報の読み取り | 認証情報・OAuth トークン・MCP シークレットは**読まない**。DTO にフィールドを持たせることすらしない |
| N-7 | セッション内容・プロジェクト情報の外部送信 | 利用枠の取得のために GitHub の API を叩くことは許容するが、**こちらから内容を送らない** |
| N-8 | GitHub 側の課金設定 (予算 / 支出上限) の変更 | **表示のみ** |
| N-9 | LLM による要約・日記生成 | 本仕様のスコープ外 |
| N-10 | 複数プロセス構成 (frontend + backend) の専用管理 UI | 起動コマンド上書き欄に複合コマンドを書く運用でカバーする |

### 2.3 前提環境

| 項目 | 前提 |
|---|---|
| OS | Windows 11。dev サーバーのプロセスツリー管理に OS 固有機能を使うため、v1 は Windows 専用でよい |
| 対象エージェント | GitHub Copilot CLI (`copilot`)、VS Code の Copilot Chat / エージェントモード |
| 課金体系 | **GitHub AI Credits による従量課金** (2026-06-01 以降。付録 A.4) |
| 権限 | 管理者権限を要求しない |
| ネットワーク | 利用枠の取得のみ GitHub SDK / API へアクセスする。それ以外は完全ローカル動作 |
| 想定規模 | プロジェクト数十件、並行セッション数件〜10 件、セッションログ数百 MB / 数百ファイル |

## 3. 用語

| 用語 | 定義 |
|---|---|
| **セッション** | Copilot の 1 回の対話セッション。一意な session id を持つ |
| **エントリポイント** | セッションを起動した経路。CLI (interactive) / CLI (background) / VS Code 拡張 / coding agent |
| **サブエージェント実行** | セッションが起動した下位エージェント・委任タスクの 1 実行。親子関係を持ち N 段の木を成す |
| **ターン (レコード)** | セッションログの 1 行 = 1 イベント |
| **トランスクリプト** | セッションの発話・ツール呼び出し・ツール出力が記録された JSONL 形式のログ |
| **AI Credit** | Copilot の従量課金の単位。トークン (入力 / 出力 / キャッシュ) 消費に応じてモデル別レートで消費される |
| **nano-AIU** | Copilot SDK がコストを報告する単位。10⁹ で割ると AI Credit |
| **クォータ** | プラン契約に含まれる利用枠。SDK の `account.getQuota` が返す `quotaSnapshots` の単位 |
| **`path_key`** | 正規化済みパス (小文字化 + 区切りを `\` に統一 + 末尾区切り除去)。プロジェクトの一意キー |

## 4. 全体構成

### 4.1 構成

```
┌──────────────────────────────────────────────────────────┐
│ 本アプリ (常駐、非昇格)                                      │
│  ┌──────────────┐   ┌────────────────────────────────┐  │
│  │ UI (2 タブ)   │◄─►│ コア                            │  │
│  │ - Copilot     │IPC│ - 差分インデクサ                  │  │
│  │ - Projects    │   │ - ライブ監視 (画面表示中のみ)      │  │
│  └──────────────┘   │ - 利用枠取得 (操作駆動 / 長周期)   │  │
│                      │ - ローカル DB (索引・集計)        │  │
│                      │ - dev サーバー管理                │  │
│                      └────────────────────────────────┘  │
│                          ▲              ▲                 │
│         読み取り専用 ─────┘              │ HTTPS           │
└──────────────────────────────────────┼──────────────────┘
   ~/.copilot/ (session-state, ide, logs)     │
   VS Code workspaceStorage/*/chatSessions     │
   ローカルプロジェクトフォルダ / git            │
                                    ┌──────────▼─────────┐
                                    │ Copilot SDK / REST  │
                                    │ (利用枠・クォータ)    │
                                    └────────────────────┘
```

### 4.2 データ取得の 3 系統

Copilot タブは**性質の異なる 3 つの取得経路**を持つ。混同しないこと。

| 系統 | 取得契機 | 対象 | 永続化 |
|---|---|---|---|
| **(1) ライブ** | 画面表示中の 2 秒ポーリング | 小さなローカル状態ファイル + PID 生存確認 + トランスクリプト末尾のシーク読み | しない (プロセス内メモリのみ) |
| **(2) インデックス** | タブ表示・更新ボタン・自動 (未取り込みの追記があるときのみ、下限 10 秒) | セッションログ全体の差分パース | する (索引・集計テーブル) |
| **(3) 利用枠** | ユーザー操作 + 長周期 (目安 5 分以上) | Copilot SDK / GitHub REST API | 直近値のみキャッシュ (任意で時系列) |

**(3) はネットワークアクセスを伴うため、絶対に (1) の 2 秒ポーリングに載せない** (NFR-04)。

プロジェクトタブは **ユーザー操作駆動のみ** (タブを開いたとき・更新ボタン)。定期ポーリングを持たない。

## 5. 機能要求: プロジェクト機能 (FR-P)

### 5.1 スキャンと一覧化

| ID | 優先度 | 要求 | 根拠 |
|---|---|---|---|
| **FR-P-01** | 必須 | スキャン対象フォルダ**直下の 1 階層のみ**を走査し、**ディレクトリのみ**を候補とする。再帰しない | 深い再帰は `node_modules` / `.venv` / `target` の除外リスト管理を招き、走査時間も読めなくなる。ファイルを候補から外せば `*.zip` 等は自然に落ちる |
| **FR-P-02** | 必須 | スキャン対象フォルダはユーザーが追加/削除できる。**未登録のときは既定フォルダ** (`%USERPROFILE%\Documents\Projects`) を**その場限りの対象として使うだけで、DB には書き込まない** | 既定フォルダを自動登録すると「削除しても次回スキャンで復活する」削除不能状態になる |
| **FR-P-03** | 必須 | 読み取れないフォルダ (存在しない / 権限なし) は警告ログを出して**スキップし、スキャン全体を失敗させない** | |
| **FR-P-04** | 必須 | **スキャン結果・git 状態・Copilot 利用状況を永続化しない**。導出データとして要求時に読み直す。永続化するのは「スキャン対象フォルダ」と「手動調整」の 2 つだけ | ディスクの現状を写しただけのデータを DB に持つと「実体は消えたのに DB に残る」「リネームで別プロジェクト扱いになる」同期ずれの世話が恒久的に発生する |
| **FR-P-05** | 推奨 | スキャン結果はプロセス内メモリにキャッシュし、**再スキャンを伴わない操作** (手動調整の保存など) では再利用する | |
| **FR-P-06** | 必須 | ディスク走査は UI スレッドを塞がない実行経路で行う | UI スレッドでの同期 IO はアプリ全体を「応答なし」にする |

### 5.2 プロジェクト種別の判定

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-P-10** | 必須 | 種別は**固定の優先順リスト**で判定する。判定材料は**マニフェストファイルの存在有無のみ** (内容は読まない) |
| **FR-P-11** | 必須 | 優先順は次表のとおり。**Next.js を Vite より必ず先に見る** |
| **FR-P-12** | 必須 | ルート直下にマニフェストが 1 つも無い場合、**1 階層下だけ**を探す。複数候補が出たら優先順位が最上位のもの、同順位ならディレクトリ名昇順で 1 つに決める。採用したサブフォルダが**作業ディレクトリ (`working_dir`)** になる |
| **FR-P-13** | 必須 | いずれにも該当しなければ「その他」として扱い、**一覧から隠さない** |
| **FR-P-14** | 推奨 | 判定は IO 非依存の純粋関数として切り出し、実データで見つかった誤判定パターンをユニットテストのケースにする |

**種別優先順リスト (FR-P-11)**

| 順位 | 種別 | 判定材料 |
|---|---|---|
| 1 | Tauri | `src-tauri/tauri.conf.json` |
| 2 | Next.js | `next.config.{js,ts,mjs,cjs,mts,cts}` |
| 3 | SvelteKit | `svelte.config.js` |
| 4 | Vite SPA | `vite.config.*` |
| 5 | Python パッケージ | `pyproject.toml` |
| 6 | Rust | `Cargo.toml` |
| 7 | Python | `requirements.txt` |
| 8 | Notebook | `*.ipynb` が 1 つ以上 |
| 9 | その他 | 上記いずれにも該当しない |

> **順序が重要な理由**: Next.js プロジェクトが Vitest 用の `vite.config.ts` を併せ持つことは珍しくなく、素朴な判定順では誤判定する。またルートにマニフェストが無くサブフォルダにあるケース、`frontend/` と `backend/` の**両方**にマニフェストがあるケースも実在するため FR-P-12 の決定規則が要る。

### 5.3 起動コマンドの解決

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-P-20** | 必須 | `package.json` の `scripts` を読み、許可リスト `["dev","build","start","preview","test","lint"]` に**実在するキーだけ**を、許可リストの順で起動候補として提示する。`test:watch` のような派生キーは含めない |
| **FR-P-21** | 必須 | 実行コマンドの解決順: ①ユーザーの起動コマンド上書き → ②`dev` があれば `npm run dev` → ③`start` があれば `npm run start` → ④空 (起動不可) |
| **FR-P-22** | 必須 | **起動が不適切なプロジェクト (本アプリ自身のソースなど) を起動不可として扱える**こと。一覧からは隠さず、起動ボタンを無効化して**理由を表示する** |
| **FR-P-23** | 必須 | 起動可否は UI のボタン無効化だけに頼らず、**バックエンド側でも再チェック**する |

### 5.4 手動調整 (override)

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-P-30** | 必須 | 次の項目をプロジェクトごとに手動調整でき、**`path_key` をキーに永続化**する: 表示名 / 起動コマンド上書き / 作業ディレクトリ上書き / 並び順 / 非表示 / アーカイブ |
| **FR-P-31** | 必須 | 手動調整は**再スキャンしても失われない** (`path_key` でマージする) |
| **FR-P-32** | 必須 | 作業ディレクトリ上書きは絶対パスでもルートからの相対パスでも受け付け、**保存時に実在するディレクトリかを検証**し、存在しなければ拒否して DB に書き込まない |
| **FR-P-33** | 推奨 | 自動判定は「候補の提示」、上書きは「最終決定」という役割分担にする。自動判定ロジックを個別事情に合わせて歪めない |

> **FR-P-32 が要る理由**: リポジトリルートを作業ディレクトリにして、起動コマンドにルートからの相対パス (`.\backend\.venv\Scripts\python.exe -m ...`) を書きたい構成が実在する。自動判定が `frontend/` を選ぶと相対パスが解決できず起動が失敗するため、上書きが必要になる。

### 5.5 git 状態

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-P-40** | 必須 | 各プロジェクトについて次を表示する: ブランチ名 / 未コミット変更の有無 / リモート (origin) の有無 / 最終コミット日時 |
| **FR-P-41** | 必須 | detached HEAD はブランチ名なしとして扱う |
| **FR-P-42** | 必須 | `.git` が存在しなければコマンドを 1 つも実行せず即座に「git 情報なし」とする |
| **FR-P-43** | 必須 | 個々のコマンドの非ゼロ終了は正常系として扱い (例: リモート未設定)、**1 プロジェクトの失敗が全体を失敗させない** |
| **FR-P-44** | 必須 | 判定対象は `working_dir` ではなく**リポジトリルート** (`root_path`) とする |
| **FR-P-45** | 推奨 | 同時実行数に上限 (目安 8) を設ける — 数十プロジェクト × 複数コマンドの一斉プロセス起動を避ける |
| **FR-P-46** | 必須 | 子プロセス起動時にコンソールウィンドウを表示しない |
| **FR-P-47** | 任意 | リモートとの ahead/behind は取得しない |

### 5.6 Copilot 利用状況の紐付け

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-P-50** | 必須 | プロジェクトごとに Copilot の利用状況を**読み取り専用**で表示する: 保持セッション数 / 最終利用日時 / 直近セッションのタイトル / 稼働中か / 直近セッションのクレジット消費・追加行数・削除行数 |
| **FR-P-51** | 必須 | セッション履歴とプロジェクトの対応付けは**履歴側に記録された作業ディレクトリ (cwd) を正規化した `path_key` の完全一致**を最優先とする |
| **FR-P-52** | 必須 | **フォルダ名フォールバック**を持つ。完全一致が無く、かつ ①その cwd が**ディスク上に存在せず**、②**同じフォルダ名を持つスキャン済みプロジェクトがちょうど 1 件**で、③そのプロジェクトにまだ完全一致の履歴が紐付いていない — の 3 条件すべてが成立するときに限り紐付ける |
| **FR-P-53** | 必須 | フォールバックで紐付けた場合は**その旨を UI に明示する** (「旧パスの履歴 (フォルダ名で照合)」等)。推測による紐付けを事実として提示しない |
| **FR-P-54** | 必須 | 同一 `path_key` に複数の履歴候補が競合したらセッション数が多い方を採用する。完全一致とフォールバックが競合したらフォールバック側を**捨てる** (合算しない) |
| **FR-P-55** | 必須 | 巨大なログの**全文パースを行わない**。最終利用日時とタイトルは**末尾数 KB**、作業ディレクトリは**先頭数十 KB** の部分読みで求める |
| **FR-P-56** | 必須 | **ファイルの mtime を判定に使わない**。中身のタイムスタンプを読む |
| **FR-P-57** | 必須 | 「稼働中」の判定は状態ファイルの存在だけでなく、**PID の生存確認を併用**する |
| **FR-P-58** | 必須 | 履歴が一切ないプロジェクトは「触ったことがない」として利用状況を持たせない (空欄で埋めない) |

> **FR-P-52 が要る理由**: エージェントは作業ディレクトリのパスをキーに履歴を保存するため、**プロジェクトフォルダを移動・リネームすると履歴との紐付けが切れる**。とくに VS Code の Copilot Chat はワークスペースフォルダの URI から導いたハッシュでセッションを保存するため、フォルダが動くと過去セッションが丸ごと孤児化する (付録 A.2)。完全一致だけに頼ると、フォルダを一度整理しただけで機能が実質使えなくなる。
>
> **FR-P-55 / 56 が要る理由**: セッションログには数 MB のファイルが実在するため全文パースは成立しない。また PC 移行やバックアップ復元により**複数ファイルが同一 mtime になる**ことがあり、mtime を信頼した判定は壊れる。

## 6. 機能要求: Copilot 稼働ダッシュボード (FR-C)

### 6.1 差分インデックス

| ID | 優先度 | 要求 | 根拠 |
|---|---|---|---|
| **FR-C-01** | 必須 | セッションログを**全期間**インデックスする。期間を区切らない | 「全期間を振り返れること」が要求そのもの |
| **FR-C-02** | 必須 | **本文 (発話・ツール呼び出し・ツール出力の全文) を DB に複製しない**。索引には `ファイルパス + バイトオフセット + バイト長 + メタデータ + 先頭 140 字程度のプレビュー` のみを保存し、本文ビューアを開いた瞬間にその 1 レコードだけをシーク読みする | 数百 MB の生テキストのうち実際に読み返されるのは「開いた 1 レコード」だけ。全文複製は使われないデータのためにディスクとメモリ帯域を倍払う |
| **FR-C-03** | 必須 | ファイルごとに**最後にパースし終えたバイトオフセット**を記録し、**追記分のみ**を差分パースする | |
| **FR-C-04** | 必須 | オフセットの更新は、対応するレコード挿入と**同一トランザクション内の最後**に行う | クラッシュしても最後にコミットが成功した位置から再開できる |
| **FR-C-05** | 必須 | **改行で終わらない末尾断片 (書きかけの最終行) は確定分から除外**し、その分をオフセットに含めない | 追記中のファイルを読むための必須の安全策 |
| **FR-C-06** | 必須 | ファイルサイズが記録より**小さく**なっていたら truncate / 入れ替わりとみなして**全再パース**する | mtime は信頼できないため、サイズとオフセットで判定する |
| **FR-C-07** | 必須 | `(ファイルパス, バイトオフセット)` に UNIQUE 制約を張り、重複挿入を無視することで**二重適用を安全にする** | |
| **FR-C-08** | 必須 | 読み込みは行単位のストリーミングで行い、**ファイル全体をメモリに載せない** | ツール出力が丸ごと 1 行に載るため、単一レコードが数百 KB〜数 MB になりうる |
| **FR-C-09** | 必須 | 一定行数 (目安 3,000 行) ごとにコミットし、**バッチ間で短いスリープ (目安 15ms) を入れて DB ロックを手放す** | 他機能の DB 利用と競合させない |
| **FR-C-10** | 必須 | インデックス実行は**バックグラウンドで行い、起動要求は即座に返す**。多重起動を防止する (実行中の再要求は黙って無視) | |
| **FR-C-11** | 必須 | 進捗を `フェーズ / 総ファイル数 / 完了数 / 現在のファイル / 累計取り込みレコード数` として通知する。通知は 250〜300ms 間隔に間引く | |
| **FR-C-12** | 必須 | 壊れた行はパース失敗として黙って読み飛ばし、**他行の処理を継続**する | |
| **FR-C-13** | 必須 | すべてのフィールドを欠落しうる前提で防御的にパースする。**読めなくなっても該当項目が空になるだけで機能全体が止まらない** | 依存先は内部形式で、予告なく変わりうる |
| **FR-C-14** | 必須 | セッション集計とサブエージェント実行履歴は**無期限保持**する。時系列サンプルのみ保持期間を設ける | 「全期間を振り返る」が要求のため。集計行は数百件規模で放置しても問題にならない |
| **FR-C-15** | 推奨 | 差分判定 (`継続 / 全再パース / 更新なし`) と末尾断片の切り捨ては純粋関数に切り出し、ユニットテストで固める | |

### 6.2 セッション集計とサブエージェント系統

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-C-20** | 必須 | セッション単位に次を集計する: 作業ディレクトリ / フォルダ名 / git ブランチ / エントリポイント / タイトル / 開始時刻 / 最終活動時刻 / ターン数 / トークン 4 種 (入力・出力・キャッシュ作成・キャッシュ読込) / **消費 AI Credits** / サブエージェント数 / 利用枠到達イベント数 |
| **FR-C-21** | 必須 | サブエージェント実行を、**親エージェント ID を持つ N 段の木**として保持する: 親子関係 / 深さ / エージェント種別 / 説明 / モデル / 開始・最終活動・終了時刻 / 状態 (`実行中 / 完了 / 拒否`) / トークン・ツール利用統計 |
| **FR-C-22** | 必須 | サブエージェント実行の**主キーは、親側と子側の両方に必ず存在する識別子**とする。片側にしか存在しない ID を主キーにしない |
| **FR-C-23** | 必須 | 親側でサブエージェント起動を見つけた時点で行を作成し、以降**同じキーでマージ**する |
| **FR-C-24** | 必須 | **バックグラウンド起動の「起動しただけ」の暫定応答を完了として扱わない**。本当の完了通知が届くまで実行中のままにする |
| **FR-C-25** | 必須 | 完了通知は**単一のソースからのみ**拾う。同じ通知が複数のレコード種別に重複して現れる場合、複数ソースから拾うと終了時刻が「どのソースを最後に処理したか」に依存する不安定な値になる |
| **FR-C-26** | 必須 | 完了通知の適用には**2 段階の確認ゲート**を通す (「同一バッチ内に起動レコードがある」または「既に該当行が存在する」もののみ適用) |
| **FR-C-27** | 必須 | 「拒否 (親が呼び出しを拒否した)」と「失敗 / 中断 (実際に起動して終わった)」を混同しない |
| **FR-C-28** | 必須 | 利用枠到達・レート制限・**セッションのクレジット上限到達**をイベントとして抽出し保持する: セッション / 発生時刻 / 種別 / リセット表示文言 / 生メッセージ |
| **FR-C-29** | 推奨 | サブエージェント側のメタ情報 (種別・説明・親の呼び出し ID・深さ・モデル) は差分の有無に関わらず毎回読み直してマージする |

> **FR-C-22 が要る理由**: 親側の呼び出しレコードと子側のログで異なる ID が振られている場合、片側にしか無い ID を主キーにすると (a) 拒否されたケースでキーを捻出できず、(b) 親の行と子のファイルが別々のインデックス実行に分かれたとき親子関係を復元できなくなり、系統図がフラットに退行する。
>
> **FR-C-24〜26 が要る理由**: バックグラウンド実行のエージェントは起動 1〜2 秒後に「起動した」という暫定応答を書き、本当の完了は数分後に別のレコードとして届くことがある。暫定応答を完了とみなすと、数分動いた実行が「1 秒」と記録される。逆に完了通知を無条件に適用すると、エージェント以外のバックグラウンド実行 (シェルコマンド等) で幽霊行ができる。

### 6.3 ライブ稼働監視

| ID | 優先度 | 要求 | 根拠 |
|---|---|---|---|
| **FR-C-40** | 必須 | 稼働中セッションを一覧表示する。判定は**状態ファイル + PID の生存確認**で行い、死んでいるものは一覧から除外する | 状態ファイルはプロセス終了時に消える保証がなく stale になりうる |
| **FR-C-41** | 必須 | ライブ監視のタイマーは**画面 (タブ) 側に置き、タブを離れたら確実に止まる**構造にする。バックエンドに常駐ポーリングループを作らない | コンポーネントのマウント/アンマウントが「タブを見ているか」と厳密に一致する。バックエンドに置くと開始/停止の往復と状態管理が増え、「離れたら確実に止まる」保証がコードから読み取れなくなる |
| **FR-C-42** | 必須 | ポーリング間隔は **2 秒**。読むのは小さなローカルファイルと PID 生存確認のみで、**ネットワークアクセスも外部プロセス起動も伴わない** | |
| **FR-C-43** | 必須 | **ウィンドウ最小化時もポーリングを停止する**。ブラウザの可視状態イベントだけに頼らず、ネイティブウィンドウの最小化を検知して通知する経路を併せ持つ | ネイティブウィンドウの最小化は WebView の `visibilitychange` に伝播しない (最小化しても `visibilityState` は `visible` のまま) |
| **FR-C-44** | 必須 | 各セッションの**活動状態**を次の 5 値で表す: `生成中 / ツール実行中 / 入力待ち / サブエージェント実行中 / 不明` | |
| **FR-C-45** | 必須 | 活動状態の判定は次の優先順で合成する: ①セッション状態のシグナル (状態ファイル / セッション開始・終了フック) が**新鮮 (目安 60 秒以内)** ならそれを最優先 → ②なければ**トランスクリプト末尾レコードのターン終了理由**から判定 → ③結果が「入力待ち / 不明」で、かつ稼働中サブエージェントが 1 件以上あれば「サブエージェント実行中」に上書きする | ①が得られないエントリポイントが存在しうるため、①だけに依存すると常に「不明」になる。**②はエントリポイントに依存せず全セッションで効く**ので、②だけでも成立する設計にしておく |
| **FR-C-46** | 必須 | **「長時間のツール実行中」と「ツール許可プロンプトで停止中」は区別できない**ことを前提とし、UI で断定しない (「ツール実行中」等の中立表現にし、補足はツールチップへ) | 両者はログ上まったく同じ形 (直近の書き込みがツール呼び出しのまま止まる) でしか現れない |
| **FR-C-47** | 必須 | 末尾レコードの読み取りは**末尾 64KB のシーク読み**で行い、見つからなければ**512KB で 1 回だけ**読み直す。ファイル全体を読まない | |
| **FR-C-48** | 必須 | `(パス, サイズ, mtime)` が前回と同じならディスクを読み直さない。アイドルなセッションは一度読めば以降読まれない。一覧から消えたセッションのキャッシュは毎回剪定する | これが無いと 2 秒ごとに全セッションの末尾を読むことになる |
| **FR-C-49** | 必須 | **末尾の物理的な最終行が本文レコードとは限らない**。末尾から遡って最初に見つかる本文レコード (ユーザー / アシスタント) を採る | 末尾付近にタイトル・添付・スナップショット等の特殊レコードが混ざる |
| **FR-C-50** | 必須 | 稼働中サブエージェント数は **DB の状態列ではなく、サブエージェントのログファイルの mtime が直近 N 秒 (目安 120 秒) 以内か**で近似する。ファイル内容は読まない | DB は更新ボタンを押すまで古いままで、「ライブ」の名に反する |
| **FR-C-51** | 必須 | **稼働中サブエージェントの「件数」と「ID 集合」を別々に算出しない**。集合を先に作り、件数はその長さとして導出する | 数字と集合が食い違いようがない形にする。別々に持つと「バッジは稼働中なのに系統図は空」という矛盾が出る |
| **FR-C-52** | 必須 | mtime 由来の稼働判定には**最大 N 秒の遅れがある**ことを既知の制約として受け入れ、UI で断定しない | mtime は「最後に書き込まれた時刻」に過ぎない |
| **FR-C-53** | 必須 | セッションカードに出す情報: フォルダ名 / エントリポイントバッジ / タイトル / 活動状態ドット / モデル名 / 稼働時間 / 最終活動 (相対時刻) / **コンテキストウィンドウ使用率** / **セッション消費クレジット** / サブエージェント数バッジ | |
| **FR-C-54** | 必須 | セッションタイトルは `インデックス済みタイトル → セッションストア / 状態ファイル由来の名前` の順にフォールバックする | |
| **FR-C-55** | 推奨 | **30 分以上アイドルなセッションは既定で非表示**にし、トグルで表示できるようにする。「指示を出したら再表示」は**状態を持たず、最終活動時刻の判定が自然に戻ることで**満たす | タイマーもフラグも持たないので、隠す/戻すの状態がずれようがない |
| **FR-C-56** | 推奨 | セッションカードを展開するとインラインでサブエージェント系統図を表示する。**サブエージェントが稼働中のセッションは自動展開**する。ただしユーザーが手動で閉じた場合と取得に失敗した場合は自動展開を抑止する | 抑止が無いと「自動展開 → 失敗 → 閉じる → 自動展開」の 2 秒ループになる |
| **FR-C-57** | 必須 | **未インデックスのセッションはエラーではなく正常系**として扱う。「まだ記録がありません」と穏やかに表示し、そのセッションについて 1 回だけインデックスを起動する | 赤いエラーを出しても、ユーザーには何をすればよいか分からない |
| **FR-C-58** | 推奨 | 画面を見ている間、**実際に未取り込みの追記があるときに限り**差分インデックスを自動起動する。判定はログの mtime と直近インデックス完了時刻の比較のみで行い、**下限間隔 10 秒**を設ける | 手動更新しか無いと「画面上は動いていないのに、更新を押すと実は動いていた」状態が常態化する。下限が無いと生成中のセッションがある間ポーリングのたびに走る |
| **FR-C-59** | 必須 | 自動インデックスの発火判定には**ログの mtime だけを使い、固定間隔で更新される値を混ぜない** | 定期リフレッシュ由来のタイムスタンプは実際の活動と無関係に進む。混ぜるとアイドル時も常に「未取り込みあり」と誤判定し、際限なく回り続ける |
| **FR-C-60** | 推奨 | 「インデックス中」バッジは**手動更新のときだけ**出す。自動実行では出さず、「最終インデックス: N 秒前」の更新を鮮度の保証とする | 10 秒ごとの点滅は視覚ノイズになる |
| **FR-C-61** | 必須 | 稼働サマリーとして「稼働中セッション数 / 稼働中サブエージェント数 / IDE ワークスペース数」を常時表示する | |

### 6.4 IDE ワークスペース

### 6.5 利用枠に対する消費率の可視化

> **本節が満たすべきことは 1 つ**: 「**契約している利用枠に対して、今どこまで使っているか**」が一目で分かること。取得手段は問わない (取得経路の要求は 6.8)。

| ID | 優先度 | 要求 |
|---|---|---|
| **FR-C-80** | 必須 | 利用枠の消費率をゲージで表示する。**性質の異なる複数の枠を並べて**表示できること。対象は ①**月次 AI Credits の消費額 / 付与額**、②**クォータの消費率とリセット日**、③**セッションのコンテキストウィンドウ使用率** |
| **FR-C-81** | 必須 | 値の出所を段階で降格させ、**UI で必ず区別表示する**: `実値 (SDK / API 由来)` → `推定 (過去実績比)` → `取得不可` |
| **FR-C-82** | 必須 | 「推定」は**過去実績との相対値であり、提供元が課金している実際の消費率ではない**ことを UI に明示する |
| **FR-C-83** | 必須 | 「取得不可」のときは**何をすれば取れるようになるか** (認証が必要 / SDK が見つからない / 対象プランでない 等) を表示する |
| **FR-C-84** | 必須 | 複数の枠を**独立に評価**する。**ある枠だけ実値がある場合、他の枠に推定値を混ぜない** |
| **FR-C-85** | 必須 | **リセット日時を過ぎた観測を除外**する — 期間がロールオーバー済みなら値は原理的に無意味。恣意的な時間しきい値より正確な基準になる |
| **FR-C-86** | 必須 | 鮮度は「取得しに行った時刻」ではなく「**値が変化したときだけ更新される観測時刻**」で判定する。値と観測時刻は必ずペアで引き継ぐ — 定期取得は値の更新と無関係に走るため、取得時刻を鮮度に使うと**期限切れの古い値が「最新」として選ばれる** |
| **FR-C-87** | 必須 | 観測からの経過時間を表示し、**一定時間 (目安 15 分) を超えたら警告色**にする |
| **FR-C-88** | 必須 | 使用率のしきい値は `90% 以上 = 危険` / `70% 以上 = 警告` / それ未満 = 通常 の 3 段階で色分けする |
| **FR-C-89** | 必須 | **消費が「額」で表される枠 (AI Credits) は、率だけでなく金額も併記する** (例: `$6.20 / $10.00 (62%)`) — 従量課金では「あと何ドル分か」が意思決定の単位になる |
| **FR-C-90** | 必須 | **付与枠を超過した分がある場合は、超過額を別建てで明示する**。100% でクランプして「上限に達した」ように見せない — 上限打ち止め設定でない限り、消費は付与額を超えて伸びる |
| **FR-C-91** | 推奨 | リセット日時までの残り時間を表示する (月次枠は日付、短期枠は残り時間) |
| **FR-C-92** | 推奨 | 推定値の算出は「直近の期間のトークン合計 ÷ 過去 30 日を 1 時間刻みでスライドさせた最大合計」とし、0〜100% にクランプする |
| **FR-C-93** | 推奨 | 推定値の再計算は全表走査を伴うため 60 秒程度の TTL キャッシュを持つ |
| **FR-C-94** | 任意 | 消費率の時系列を保存し、推移グラフを表示する。保存する場合は保持期間 (目安 30 日) を設けて間引く |
| **FR-C-95** | 任意 | セッション単位のクレジット上限 (session limit) が設定されている場合、その値と現在の消費を並べて表示する |

## 7. データ要求 (DR)

### 7.1 永続化の原則

| ID | 優先度 | 要求 |
|---|---|---|
| **DR-01** | 必須 | 永続化は単一のローカル DB (SQLite 等) に一本化する。**ただし「何でも保存する」という意味ではない** |
| **DR-02** | 必須 | **導出データ (ディスクの現状を写したもの) は永続化しない**: プロジェクトスキャン結果 / 種別判定 / git 状態 / Copilot 利用状況 / dev サーバーのログ |
| **DR-03** | 必須 | **例外は「一覧性のための索引」のみ**。数百ファイルを毎回全走査してはセッション一覧すら描けないため、セッションログの索引だけは持つ |
| **DR-04** | 必須 | スキーマ変更はバージョン付きマイグレーションで行い、破壊的変更を含むリリースでは**適用前バックアップ**を残す |
| **DR-05** | 推奨 | 他アプリが所有する SQLite を読む場合は、**読み取り専用で開くか、コピーしてから読む**。書き込みロックを取らない (OQ-05) |
| **DR-06** | 必須 | 認証トークン・API キーを DB に保存しない (FR-C-141) |
| **DR-07** | 必須 | **保持期間を設けたテーブルを作るなら、書き込みも必ず実装する**。間引き処理だけが動く未使用テーブルを残さない |

> **SDK は TypeScript / Python / Go / .NET / Java / Rust で提供されている。** ✅

### A.4 課金体系 (2026-06-01 以降)

| 項目 | 内容 |
|---|---|
| 単位 | **`GitHub AI Credits`**。従来のプレミアムリクエスト単位 (PRU) は 2026-06-01 に廃止された |
| 消費の仕方 | **トークン (入力 / 出力 / キャッシュ) 消費 × モデル別レート**。「1 リクエスト = 1 消費」ではない |
| 付与 | 月額プラン料金と**同額のクレジットが毎月付与**される (Pro `$10/月` に `$10` 分、Pro+ `$39/月` に `$39` 分、Business `$19/user/月` に `$19` 分、Enterprise `$39/user/月` に `$39` 分) |
| 超過 | 予算設定により「公開レートで超過分を課金」または「上限で打ち止め」を選べる (enterprise / cost center / ユーザー単位) |
| 除外 | **コード補完と Next Edit Suggestions はプランに含まれ、従量課金されない** |
| 例外 | **年額 Pro / Pro+ の既存契約は満了までリクエスト課金のまま**。移行されない |
| SDK の単位 | コストは **nano-AIU** で報告される (10⁹ で割ると AI Credit)。`1 AI Credit = $0.01` という換算は二次情報のため、実装前に実測で確認する (OQ-06) |
| 残高の確認 | `github.com/settings/billing` の課金概要 |

> **仕様への影響**:
> 1. **「枠」は月次クレジット額が主役**になる。5 時間 / 週次のような**短期ローリングウィンドウは存在しない**ため、ゲージは「月次クレジット + クォータ + コンテキスト使用率」の構成にする。
> 2. **率だけでなく額の表示が要る** (FR-C-89)。従量課金では「あと何ドル分か」が判断単位になる。
> 3. **超過を 100% でクランプしない** (FR-C-90)。上限打ち止め設定でない限り、消費は付与額を超えて伸びる。
> 4. **課金体系は実際に一度変わっている。** 単価・付与額・枠の名前をコードに埋め込まず、実行時に読む (FR-C-134)。
