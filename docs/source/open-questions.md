## この環境での初期観測 (2026-09-08)

`~/.copilot/` を**読み取り専用で**一覧しただけの、ごく浅い観測。プローブ (T-0.1〜0.6) の代わりにはならない。

| 観測 | 内容 | 影響 |
|---|---|---|
| `~/.copilot/` の中身 | `config.json` / `ide/` / `logs/` の 3 つのみ。**`session-state/` が存在しない** | OQ-01 / OQ-02 の調査に**先立って、CLI セッションを実際に作る必要がある**。段階 0 の前提作業 |
| `~/.copilot/ide/*.lock` | JSON。キーは `socketPath` / `scheme` / **`headers`** / `pid` / `ideName` / `timestamp` / `workspaceFolders` / `isTrusted`。1 ファイル 357 バイト | **`headers` は認証情報を含みうる。読まない・DTO に定義しない (INV-2 / FR-C-72)。**`pid` / `ideName` / `workspaceFolders` は FR-C-70 にそのまま使える |
| `~/.copilot/logs/process-<epoch_ms>-<pid>.log` | 1 行 = `ISO8601 [LEVEL] メッセージ` のテキスト。「CLI server ready (stdio mode)」等 | ファイル名の PID が稼働検出の手掛かりになる (OQ-04)。**ただしファイル名の数字は epoch ミリ秒で、要求が書く `{timestamp}` と一致する** |
| VS Code `workspaceStorage` | 20 ワークスペースのうち **15 に `chatSessions/` が存在** | OQ-03 の調査対象がこの環境に十分ある。ハッシュ再計算と cwd 逆引きの両方を試せる |

**この 4 行以外は何も分かっていない。**

この観測は `node tools/probe/copilot-layout.mjs` (T-0.1) の出力から取っている。同じ数字は
`tools/probe-out/copilot-layout.json` に残るが、**コミットしない** (個人のセッション内容を含みうる)。

## OQ-04 — 稼働中セッションの検出方法

**状態**: 一部判明

| 項目 | 内容 |
|---|---|
| 知りたいこと | `~/.copilot/ide/` と `logs/process-*.log` から**読み取り専用で**稼働判定できるか。できない場合、`sessionStart` / `sessionEnd` フックが**どのエントリポイントで発火するか** |
| 確認方法 | T-0.4。CLI interactive / CLI background / VS Code 拡張 / coding agent の 4 経路で実際に動かす |
| 影響範囲 | FR-C-40〜45 |

**観測できた範囲**

- `ide/*.lock` に `pid` と `workspaceFolders` がある → **VS Code 経路は読み取り専用で判定できる見込み**
- `logs/process-<epoch_ms>-<pid>.log` のファイル名から PID が取れる → CLI 経路の手掛かりになる
- **ただし、lock ファイルがプロセス終了時に必ず消える保証は未確認。**PID 生存確認との併用が必要 (FR-C-40 / FR-P-57)

**未確認**: CLI background と coding agent の経路。セッション ID と PID の対応。lock の stale 具合。

読み取り専用で足りれば、N-5 の不変条件を一切崩さずに済む。**フックの利用は最後の手段** (設定ファイルへの書き込みを伴うため、ADR-0012 と衝突する)。
