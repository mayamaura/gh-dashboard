## 1. 層

| 層 | 対象 | 道具 | 実行 |
|---|---|---|---|
| **A. 純粋関数** | 種別判定 / パス正規化 / 差分判定 / 末尾断片 / 木構築 / URL 抽出 / 活動状態 / 利用枠の降格 | `cargo test` / `vitest` | 常時。**ここが本体** |
| **B. DB** | マイグレーション / 冪等性 / UNIQUE 制約 | `cargo test` (一時ファイル DB) | 常時 |
| **C. 読み取り専用プローブ** | 実データ・実 API への疎通 | `tools/probe/*.mjs` | 手動。**判定はせず数字を出す** |
| **D. 実機確認** | UI の挙動、プロセス終了、最小化での停止 | 手動 (チェックリスト) | 各段階の完了判定 |

> [!注意]
> **NFR-53: 「テストが通る」で完了としない。実際にアプリを起動して挙動を確認してから完了とする。**
> A と B がいくら緑でも、D を通っていない機能は未完成として扱う。

## 2. 層 A — 純粋関数のテスト一覧

NFR-50 が名指ししている 8 つ。それぞれ「壊れ方」が要求に書かれているので、テストケースは**そこから作る**。

### 2.1 種別判定 (`projects::detect`) — FR-P-10〜14

| ケース | 期待 |
|---|---|
| `src-tauri/tauri.conf.json` あり + `package.json` あり | `tauri` |
| `next.config.ts` と `vite.config.ts` の**両方**あり | `nextjs` (**Vite を先に見ると誤判定する。FR-P-11**) |
| `next.config.mjs` / `.cjs` / `.mts` / `.cts` | いずれも `nextjs` |
| `svelte.config.js` あり | `sveltekit` |
| `pyproject.toml` と `requirements.txt` の両方 | `python_package` |
| `*.ipynb` が 1 つ | `notebook` |
| ルートに何もなく `frontend/vite.config.ts` だけ | `vite`、`working_dir = frontend` (FR-P-12) |
| ルートに何もなく `frontend/` と `backend/pyproject.toml` の両方 | 優先順位が上のものを採る。同順位なら**ディレクトリ名昇順** (FR-P-12) |
| どれにも該当しない | `other`。**一覧から隠さない** (FR-P-13) |

判定材料は**マニフェストの存在有無だけ**。中身を読まない。テストはファイル名の配列を渡すだけで書ける形にする。

### 2.2 パス正規化 (`util::path_key`) — 用語定義

| 入力 | 期待 |
|---|---|
| `D:\Projects\Foo` | `d:\projects\foo` |
| `D:/Projects/Foo/` | `d:\projects\foo` |
| `d:\projects\foo\` | `d:\projects\foo` |
| `\\server\share\proj` | UNC を壊さない |
| 空文字 | エラーまたは `None` (パニックしない) |

### 2.3 差分判定 (`copilot::delta`) — FR-C-03/05/06

| 記録済みオフセット | 記録済みサイズ | 現在サイズ | 期待 |
|---|---|---|---|
| 0 | 0 | 1000 | 全パース (0 から) |
| 500 | 500 | 1200 | 継続 (500 から) |
| 500 | 500 | 500 | 更新なし |
| 500 | 800 | 300 | **全再パース** (truncate / 入れ替わり。FR-C-06) |
| 500 | 500 | 499 | **全再パース** |

**mtime を入力に取らないこと自体をテストで固定する** (引数に mtime が無いことがそのまま担保になる)。

### 2.4 末尾断片の切り捨て (`copilot::delta`) — FR-C-05

| 入力バイト列 | 期待する確定分 | 期待するオフセット増分 |
|---|---|---|
| `{"a":1}\n{"b":2}\n` | 2 行 | 全体 |
| `{"a":1}\n{"b":2` | 1 行 | 1 行目まで |
| `{"a":1}` (改行なし) | 0 行 | 0 |
| `\n` のみ | 0 行 (空行) | 1 |
| 末尾が `\r\n` | 行として確定 | 全体 |

### 2.5 木構築 (`copilot::tree`) — FR-C-113/114

| ケース | 期待 |
|---|---|
| 親 → 子 → 孫 | 3 段の木 |
| `parent_agent_id` が NULL | セッション直下 |
| 親が存在しない (孤児) | **ルート直下に置く。捨てない** (FR-C-113) |
| A → B → A の循環 | **無限ループしない**。循環を切ってガードする (FR-C-113) |
| 生データの `depth` が実際の階層と食い違う | **`depth` を無視して親子関係を採る** (FR-C-114) |
| 同じ親に複数の子 | 開始時刻順 |

系統図とガントが同じ入力から同じ行順を返すことをテストで固定する。

### 2.6 URL 抽出 (`util::url_detect`) — FR-P-63

| 入力行 | 期待 |
|---|---|
| `Local:   http://localhost:5173/` | `http://localhost:5173/` |
| `➜  Local:   http://127.0.0.1:3000/` | 取れる (装飾記号に強い) |
| `Running on http://0.0.0.0:8000` | `http://localhost:8000` に読み替える (0.0.0.0 はブラウザで開けない) |
| `Serving at https://localhost:5173` | https を保つ |
| `Compiled successfully` | `None` |
| ANSI エスケープ付き | 除去してから抽出 |

**ポートは自動採番されるため、設定値からは決められない。**出力からしか取れない。

### 2.7 活動状態の合成 (`copilot::activity`) — FR-C-44/45

優先順は ① 状態シグナルが新鮮 (60 秒以内) → ② 末尾レコードのターン終了理由 → ③ 稼働中サブエージェントがあれば上書き。

| 状態シグナル | 末尾レコード | 稼働中サブエージェント | 期待 |
|---|---|---|---|
| 新鮮 = 生成中 | ツール呼び出し | 0 | `generating` (① が最優先) |
| 古い (61 秒前) | ツール呼び出しで停止 | 0 | `tool_running` (② に落ちる) |
| なし | ターン正常終了 | 0 | `waiting_input` |
| なし | ターン正常終了 | 2 | **`subagent_running`** (③ が上書き) |
| なし | 解釈できない | 0 | `unknown` |
| なし | 解釈できない | 1 | **`subagent_running`** |

> [!注意]
> **「長時間のツール実行中」と「ツール許可プロンプトで停止中」を区別する分岐を書かない** (FR-C-46)。両者はログ上まったく同じ形でしか現れない。`tool_running` の 1 値に寄せ、UI で断定しない。

### 2.8 利用枠ビューの降格 (`copilot::quota`) — FR-C-80〜92

| 入力 | 期待 |
|---|---|
| SDK 成功 | `actual(sdk)` |
| SDK 失敗 → REST 成功 | `actual(rest)` |
| 両方失敗 → 推定可 | `estimated` + 「推定」ラベル |
| すべて不可 | `unavailable` + **「何をすれば取れるか」が入っている** (FR-C-83) |
| 枠 A は実値、枠 B は取得不可 | **B に推定を混ぜない** (FR-C-84) |
| `entitlement = -1` | 「無制限」。**率を計算しない。0 除算もマイナス率も出さない** (FR-C-131) |
| `used > entitlement` | `used_pct > 100` を許す。**100 でクランプしない**。超過額を別建て (FR-C-90) |
| `reset_at` が現在より過去 | **その観測を除外する** (FR-C-85) |
| `observed_at` が 16 分前 | 警告色 (FR-C-87) |
| `used_pct` = 70 / 89 / 90 | 警告 / 警告 / 危険 (FR-C-88) |

**`received_at` を鮮度判定に使ったら落ちるテスト**を必ず 1 本入れる (FR-C-86)。

## 3. 層 B — DB のテスト

| ケース | 期待 |
|---|---|
| 空 DB にマイグレーション適用 | 全テーブルができる。`user_version` が上がる |
| 同じマイグレーションを 2 回適用 | 冪等。壊れない |
| 同じ `(file_path, byte_offset)` を 2 回挿入 | 2 件目は無視される (FR-C-07) |
| インデックスを 2 回連続実行 | **2 回目の新規レコードが 0 件** (NFR-02) |
| 途中でトランザクションを中断 | オフセットが進んでいない = 取りこぼしなく再開できる (FR-C-04) |
| `quota_samples` の間引き | 30 日より古い行が消え、新しい行は残る (DR-07) |

## 4. 層 C — 読み取り専用プローブ

実データと実 API に対して**数字を出すだけ**のスクリプト。合否判定をせず、OQ を潰す材料を作る (NFR-52)。

| スクリプト | 出すもの | 対応 OQ |
|---|---|---|
| `tools/probe/copilot-layout.mjs` | `~/.copilot` 配下の構成・ファイル数・総容量・最大ファイルサイズ | OQ-10 |
| `tools/probe/jsonl-shape.mjs` | 1 レコード = 1 行か / 行内改行の有無 / BOM の有無 / 行長分布 | **OQ-02 (設計の分水嶺)** |
| `tools/probe/record-kinds.mjs` | レコード種別ごとの件数・サイズ・出現位置・フィールド出現率 | OQ-01 / OQ-07 |
| `tools/probe/vscode-sessions.mjs` | `workspaceStorage` のハッシュと中身から cwd を逆引きできるか | OQ-03 |
| `tools/probe/live-detect.mjs` | `ide/*.lock` と `logs/process-*.log` から稼働セッションを判定できるか | OQ-04 |
| `tools/probe/quota-sdk.mjs` | `account.getQuota` が個人アカウントで何を返すか | **OQ-06** |

> [!注意]
> プローブは**読み取り専用**。書き込み・設定変更を一切行わない (INV-1)。
> 出力は `tools/probe-out/` に置き、**コミットしない** (個人のセッション内容を含みうる)。`.gitignore` 済み。
> プローブが値を表示するときも、認証情報に相当するフィールドは伏せる (INV-2)。

## 5. 層 D — 実機確認チェックリスト

各段階の完了条件。**ここを通らないものは未完成。**

### 段階 1〜2 (プロジェクト基盤 / git・利用状況)

- [ ] 実フォルダで一覧が出る。種別の誤判定がない
- [ ] Next.js + Vitest 構成が `nextjs` と判定される
- [ ] `.git` の無いフォルダで git コマンドが 1 つも実行されない
- [ ] フォルダをリネームしても、フォルダ名フォールバックで履歴が紐付く
- [ ] フォールバックで紐付いた行に「旧パスの履歴」表示が出る (FR-P-53)
- [ ] 履歴が無いプロジェクトが 0 埋めされていない

### 段階 3 (dev サーバー)

- [ ] 起動 → URL が自動検出されて表示される
- [ ] **タスクマネージャーからアプリを強制終了 → 子プロセスが 1 つも残らない** (FR-P-61)
- [ ] ウィンドウを閉じてトレイ常駐 → dev サーバーは**止まらない** (FR-P-62)
- [ ] アプリ終了 → 全 dev サーバーが止まる
- [ ] 停止済みのものに再度停止 → エラーにならない (FR-P-66)
- [ ] `explorer.exe` で開く → 成功扱いになる (終了コード 1 でも。FR-P-72)

### 段階 4 (差分インデックス)

- [ ] 初回が実データで 5 秒以内に完走 (NFR-01)
- [ ] 2 回目が 1 秒未満、**新規レコード 0 件** (NFR-02)
- [ ] 実行中に CPU が 1 コア換算 15% を超えない (NFR-04)
- [ ] インデックス中にファイルが追記されても壊れない
- [ ] 壊れた行があっても止まらず、件数が UI に出る

### 段階 5 (ライブ監視)

- [ ] **タブを離れるとポーリングが止まる** (ログで確認)
- [ ] **ウィンドウを最小化するとポーリングが止まる** (FR-C-43。`visibilitychange` だけでは止まらないことも確認)
- [ ] 死んだセッションが一覧から消える
- [ ] アイドルなセッションでディスクが読み直されない (FR-C-48)
- [ ] サブエージェントのバッジ件数と系統図の行数が一致する (FR-C-51)
- [ ] 未インデックスのセッションで赤いエラーが出ない (FR-C-57)

### 段階 6 (利用枠)

- [ ] 実値 / 推定 / 取得不可 のラベルが実機で正しく切り替わる
- [ ] 額と率の両方が出る (`$6.20 / $10.00 (62%)`)
- [ ] 超過時に 100% でクランプされず、超過額が別建てで出る
- [ ] ネットワークを切っても画面操作がブロックされない (NFR-07)
- [ ] 取得中も他のタブが操作できる

### 段階 7 (振り返り UI)

- [ ] 系統図とガントの階層が一致する (FR-C-114)
- [ ] 本文ビューアが 1 レコードだけを読む (大きなセッションでも即座に開く)
- [ ] タブを切り替えてもインデックス進捗が消えない (FR-C-161)

## 6. 入力操作の検証

ドラッグ等の検証に**合成イベント (`dispatchEvent`) を使わない** (NFR-54)。合成イベントはハンドラの配線しか検証できず、実際の不具合を素通りさせる。実入力相当のイベント注入を使う。
