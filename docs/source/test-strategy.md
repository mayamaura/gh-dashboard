## 2. 層 A — 純粋関数のテスト一覧

NFR-50 が名指ししている 8 つ。それぞれ「壊れ方」が要求に書かれているので、テストケースは**そこから作る**。

### 2.1 種別判定 (`projects::detect`) — FR-P-10〜14

| ケース | 期待 |
|---|---|
| `src-tauri/tauri.conf.json` あり + `package.json` あり | `tauri` |
| `next.config.ts` と `vite.config.ts` の**両方**あり | `nextjs` (**Vite を先に見ると誤判定する。FR-P-11**) |
| `next.config.mjs` / `.cjs` / `.mts` / `.cts` | いずれも `nextjs` |
| `svelte.config.js` あり | `sveltekit` |
| `pyproject.toml` と `requirements.txt` の両方 | `python_package` |
| `*.ipynb` が 1 つ | `notebook` |
| ルートに何もなく `frontend/vite.config.ts` だけ | `vite`、`working_dir = frontend` (FR-P-12) |
| ルートに何もなく `frontend/` と `backend/pyproject.toml` の両方 | 優先順位が上のものを採る。同順位なら**ディレクトリ名昇順** (FR-P-12) |
| どれにも該当しない | `other`。**一覧から隠さない** (FR-P-13) |

判定材料は**マニフェストの存在有無だけ**。中身を読まない。テストはファイル名の配列を渡すだけで書ける形にする。

### 2.3 差分判定 (`copilot::delta`) — FR-C-03/05/06

| 記録済みオフセット | 記録済みサイズ | 現在サイズ | 期待 |
|---|---|---|---|
| 0 | 0 | 1000 | 全パース (0 から) |
| 500 | 500 | 1200 | 継続 (500 から) |
| 500 | 500 | 500 | 更新なし |
| 500 | 800 | 300 | **全再パース** (truncate / 入れ替わり。FR-C-06) |
| 500 | 500 | 499 | **全再パース** |

**mtime を入力に取らないこと自体をテストで固定する** (引数に mtime が無いことがそのまま担保になる)。

### 2.4 末尾断片の切り捨て (`copilot::delta`) — FR-C-05

| 入力バイト列 | 期待する確定分 | 期待するオフセット増分 |
|---|---|---|
| `{"a":1}\n{"b":2}\n` | 2 行 | 全体 |
| `{"a":1}\n{"b":2` | 1 行 | 1 行目まで |
| `{"a":1}` (改行なし) | 0 行 | 0 |
| `\n` のみ | 0 行 (空行) | 1 |
| 末尾が `\r\n` | 行として確定 | 全体 |

### 2.5 木構築 (`copilot::tree`) — FR-C-113/114

| ケース | 期待 |
|---|---|
| 親 → 子 → 孫 | 3 段の木 |
| `parent_agent_id` が NULL | セッション直下 |
| 親が存在しない (孤児) | **ルート直下に置く。捨てない** (FR-C-113) |
| A → B → A の循環 | **無限ループしない**。循環を切ってガードする (FR-C-113) |

| 同じ親に複数の子 | 開始時刻順 |

系統図とガントが同じ入力から同じ行順を返すことをテストで固定する。

### 2.6 URL 抽出 (`util::url_detect`) — FR-P-63

| 入力行 | 期待 |
|---|---|
| `Local:   http://localhost:5173/` | `http://localhost:5173/` |
| `➜  Local:   http://127.0.0.1:3000/` | 取れる (装飾記号に強い) |
| `Running on http://0.0.0.0:8000` | `http://localhost:8000` に読み替える (0.0.0.0 はブラウザで開けない) |

| ANSI エスケープ付き | 除去してから抽出 |

**ポートは自動採番されるため、設定値からは決められない。**出力からしか取れない。

### 2.7 活動状態の合成 (`copilot::activity`) — FR-C-44/45

優先順は ① 状態シグナルが新鮮 (60 秒以内) → ② 末尾レコードのターン終了理由 → ③ 稼働中サブエージェントがあれば上書き。

| 状態シグナル | 末尾レコード | 稼働中サブエージェント | 期待 |
|---|---|---|---|
| 新鮮 = 生成中 | ツール呼び出し | 0 | `generating` (① が最優先) |
| 古い (61 秒前) | ツール呼び出しで停止 | 0 | `tool_running` (② に落ちる) |
| なし | ターン正常終了 | 0 | `waiting_input` |
| なし | ターン正常終了 | 2 | **`subagent_running`** (③ が上書き) |
| なし | 解釈できない | 0 | `unknown` |
| なし | 解釈できない | 1 | **`subagent_running`** |

> [!注意]
> **「長時間のツール実行中」と「ツール許可プロンプトで停止中」を区別する分岐を書かない** (FR-C-46)。両者はログ上まったく同じ形でしか現れない。`tool_running` の 1 値に寄せ、UI で断定しない。

### 2.8 利用枠ビューの降格 (`copilot::quota`) — FR-C-80〜92

| 入力 | 期待 |
|---|---|
| SDK 成功 | `actual(sdk)` |
| SDK 失敗 → REST 成功 | `actual(rest)` |
| 両方失敗 → 推定可 | `estimated` + 「推定」ラベル |
| すべて不可 | `unavailable` + **「何をすれば取れるか」が入っている** (FR-C-83) |
| 枠 A は実値、枠 B は取得不可 | **B に推定を混ぜない** (FR-C-84) |
| `entitlement = -1` | 「無制限」。**率を計算しない。0 除算もマイナス率も出さない** (FR-C-131) |
| `used > entitlement` | `used_pct > 100` を許す。**100 でクランプしない**。超過額を別建て (FR-C-90) |
| `reset_at` が現在より過去 | **その観測を除外する** (FR-C-85) |
| `observed_at` が 16 分前 | 警告色 (FR-C-87) |
| `used_pct` = 70 / 89 / 90 | 警告 / 警告 / 危険 (FR-C-88) |

**`received_at` を鮮度判定に使ったら落ちるテスト**を必ず 1 本入れる (FR-C-86)。

## 4. 層 C — 読み取り専用プローブ

実データと実 API に対して**数字を出すだけ**のスクリプト。合否判定をせず、OQ を潰す材料を作る (NFR-52)。

実行方法は共通で:

```
node tools/probe/<名前>.mjs          人が読む形
node tools/probe/<名前>.mjs --json   JSON だけ
COPILOT_HOME=<path> node tools/probe/<名前>.mjs   ~/.copilot の場所を上書き
```

| スクリプト | 調べるもの | OQ |
|---|---|---|
| `copilot-layout.mjs` | 構成・ファイル数・総容量・最大サイズ | OQ-10 |
| `jsonl-shape.mjs` | 1 レコード 1 行 / BOM / 改行コード / 行長分布 / **バイトオフセット往復検証** | OQ-02 |
| `record-kinds.mjs` | レコード種別ごとの件数・バイト数、フィールド出現率、サブエージェント候補キー | OQ-01 / OQ-07 |
| `live-detect.mjs` | `ide/*.lock` と `logs/process-*.log` の PID 生存・対応 | OQ-04 |
| `vscode-sessions.mjs` | `workspaceStorage` のハッシュ再計算と `chatSessions` の中身 | OQ-03 |
| `quota-sdk.mjs` | `account.getQuota` / `getCurrentAuth` / `models.list` の戻り値 | OQ-06 / OQ-08 |
| `quota-rest.mjs` | 公開課金 API 10 件の status、`copilot_internal/user` の中身、SDK との突き合わせ | OQ-12 / OQ-06 |

`quota-sdk.mjs` だけは Copilot SDK が要ります。**リポジトリの `package.json` には足しません** (NFR-10)。準備はこう書いてください:

```
mkdir -p tools/probe-sdk && cd tools/probe-sdk
npm init -y && npm install @github/copilot-sdk
```

`COPILOT_SDK_PATH` で別の場所を指すこともできます。SDK が無い場合は「SDK 未導入」と出して正常終了します。

> [!注意]
> プローブは**読み取り専用**。書き込み・設定変更を一切行わない (INV-1)。
> 出力は `tools/probe-out/` (`.gitignore` 済み)。**個人のセッション内容を含みうるのでコミットしない**。
> **実データを作るときは `COPILOT_HOME` を使い捨てディレクトリに向ける。**ユーザーの実 `~/.copilot` を測定のために汚さない (INV-1)

## 6. 入力操作の検証

ドラッグ等の検証に**合成イベント (`dispatchEvent`) を使わない** (NFR-54)。合成イベントはハンドラの配線しか検証できず、実際の不具合を素通りさせる。実入力相当のイベント注入を使う。
