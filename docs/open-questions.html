T-4.11 の結論 — 利用枠到達レコードは実データでも未観測

FR-C-28 のレコード種別は、実データ 1,041 レコードを走査しても確認できなかった (OQ-01 のまま)。 quota / rate limit / credit / exceeded / usage limit / 「上限に達」等で type 値と本文系フィールド (data.content / data.result.content / data.result.detailedContent / data.reasoningText) を走査して 0 件。キーワードに一致した 19 の data パスはすべて UUID の部分一致 (…429… 等) による誤検出だった。

したがって quota_events への書き込み経路 (store::insert_quota_event と indexer の呼び出し口) は用意したが、抽出関数 parser::parse_quota_event は常に None を返す空実装にしてある。推測した種別名をコードに埋め込んでいない — 決め打ちした名前は実物と一致しなければ永久に 0 件のままで、しかも「実装済み」に見えてしまう。実物を観測したら parse_quota_event に条件を 1 つ足せば通る。
